# 反重力启动台（Windows x64）

面向 **Antigravity 桌面版**的整合启动器：启动客户端时自动应用地区适配补丁，并将客户端进程接入你已有的本地代理；客户端退出后，自动恢复原版文件。

[下载 v1.0.2](https://github.com/h1j9/antigravity-startpad/releases/tag/v1.0.2)

> 启动台不是代理软件，也不提供代理节点、Google 账号或订阅。你需要自行准备能够正常联网的代理软件，并知道它提供的本地代理地址和端口。

## 这个软件解决什么问题

### 1. 客户端登录不跳转、地区适配异常

整合第一个项目的桌面版补丁逻辑，在启动前处理 `resources/bin/language_server.exe`。启动台会先保存原版备份，并在退出后恢复，避免每次手动寻找文件、打补丁和还原。

### 2. 想让 Antigravity 使用代理，但不想开启 TUN 或修改系统代理

启动台只为它启动的 Antigravity 进程注入 HTTP/SOCKS5 代理环境变量和 Chromium 代理参数，不改变其他程序的联网方式，也不写系统代理设置。`localhost`、`127.0.0.1` 和 `::1` 始终保持直连。

### 3. 补丁工具、代理启动器和恢复步骤分散

两个项目的功能被合并为一个桌面工具，统一完成客户端定位、代理检查、原版备份、补丁、启动、进程监测和退出恢复，并提供明确的状态与运行记录。

## 使用前需要准备什么

- **Windows x64**，并已安装 Antigravity 桌面版。
- 一个已经配置好、可以正常联网的代理软件。**不限定 Clash**，其他代理软件也可以。
- 该代理软件提供的本地 **HTTP CONNECT 或 SOCKS5** 监听地址和端口；同时支持两种协议的混合端口也可以使用。
- 完全退出 Antigravity，包括托盘中的旧实例。

代理端口没有统一固定值。请在代理软件的监听、入站、端口或连接设置页面中自行查看，以实际显示为准。启动台不会替你选择或验证代理节点是否适合你的账号，只会检查填写的本地代理能否连接相关服务。

## 日常使用

1. 打开你的代理软件，确认代理已启用，并记下本地监听地址和端口。
2. 打开“反重力启动台”，在“设置”中填写对应的代理地址。HTTP 或混合端口使用 `http://` 协议，SOCKS5 端口使用 `socks5://` 协议。
3. 首次打开时，如果自动检查提示代理不可达，说明填写的地址或端口未能连接，并不是补丁损坏。修改设置后重新检查或启动即可。
4. 点击“启动反重力”。启动台会依次检查客户端和代理、备份并应用补丁、注入进程级代理，然后启动 Antigravity。
5. 使用完毕后正常关闭 Antigravity。启动台会等待 Antigravity 与 `language_server.exe` 全部退出，再从原版备份恢复文件并复核 SHA-256。

“打开启动台后自动启动”和“反重力退出后恢复原版”默认开启，可以在设置中调整。

当前已经由第一个项目打好补丁也可以使用：启动台会核验现有 `language_server.exe.agybak` 是否属于同一版本，核验通过后接管备份，不会重复写入二进制。

## 启动和退出时分别发生了什么

**启动时：**

1. 自动定位 Antigravity，也允许手动选择 `Antigravity.exe`。
2. 通过真实 HTTP CONNECT / SOCKS5 握手检查本地代理。
3. 核验文件特征与版本，保存原版备份，再应用桌面版补丁。
4. 注入代理环境变量和 Chromium 参数，仅启动目标客户端。

**退出时：**

- 进程级代理环境随客户端退出自然消失，不会残留在系统代理中。
- 默认从启动台保存的原版备份恢复 `language_server.exe`，而不是再次猜测或反向修改二进制。
- 如果客户端已经更新、文件被第三方改变、备份损坏或版本不对应，启动台会停止覆盖并保留现场与备份。

## 界面与退出行为

- **启动**：显示客户端、文件补丁、本地代理状态和运行记录。
- **设置**：代理地址、打开后自动启动、退出后恢复原版。
- **恢复原版**：仅在 Antigravity 已退出时可用。
- 反重力运行时关闭启动台窗口，会缩到托盘继续监测。
- 从托盘退出启动台时，如反重力仍在运行，会询问是否结束客户端；取消则不退出。
- 异常断电或强杀启动台可能来不及恢复。下次打开后可先点“恢复原版”。

## 适用范围与限制

- 只处理 Windows x64 桌面版的 `resources/bin/language_server.exe`，不包含 IDE、CLI 或 VS Code 扩展补丁。
- 不开启 TUN，不修改系统代理，不写系统代理注册表。
- 原版备份独立保存在启动台用户数据目录，可从界面“备份目录”打开。
- 补丁只处理本地客户端判定，不能保证 Google 服务端账号资格、订阅、配额或地区审核结果。
- 成品未购买代码签名证书，Windows SmartScreen 可能提示未知发布者。

## 从源码运行与构建

```powershell
npm install
npm test
$env:AG_STARTPAD_NO_AUTO='1'
npm start
```

设置 `AG_STARTPAD_NO_AUTO=1` 只是便于开发时查看界面，避免打开后自动启动客户端。正常使用打包版无需设置。

```powershell
npm run dist:win
```

产物在 `dist/`：NSIS 安装版与 portable 免安装版。
